# Зависимости и версии

Что используется, зачем и почему именно эта версия. Любое изменение версии —
запись в `CHANGELOG.md` и правка этого файла.

Проверено: 23.11.2026.

---

## 1. Платформа и тулчейн

| Компонент | Версия | Зачем |
|---|---|---|
| PlatformIO Core | **6.2.0** | Сборка, прошивка, тесты |
| `pioarduino/platform-espressif32` | **55.03.313** | Единственная платформа с поддержкой ESP32-P4 |
| Arduino ESP32 core | **3.3.13** | Внутри платформы; даёт Wi-Fi через C6 из коробки |
| ESP-IDF | **5.5.6** | Внутри платформы; `esp32-hal-hosted.c` с правильными пинами |
| Toolchain | `riscv32-esp-elf` | P4 — RISC-V, не Xtensa |
| esptool | **5.4.0** | Прошивка и дампы; корректно определяет P4 rev < 3.0 |

### Почему 55.03.313, а не другая

| Версия | Core | IDF | Board `m5stack-tab5-p4` | Wi-Fi без костылей |
|---|---|---|---|---|
| 54.03.21 | 3.2.1 | 5.4.2 | нет | нет |
| 55.03.34 | 3.3.4 | 5.5.1 | есть | **нет** (баг пинов SDIO) |
| 55.03.35 | 3.3.5 | 5.5.1 | есть | да |
| **55.03.313** | **3.3.13** | **5.5.6** | **есть** | **да** |
| 61.04.00 | 4.0.0 | 6.1.1 | есть | да, но другая мажорная ветка |

Ошибка в 3.3.1–3.3.4: `esp32-hal-hosted.c` не включал `pins_arduino.h`, из-за
чего брались SDIO-пины EV-борды вместо Tab5 и инициализация падала
(`sdmmc_init_ocr: send_op_cond (1) returned 0x107`, MAC `00:00:00:00:00:00`).
Проверено в исходниках тегов: в 3.3.13 `#include "pins_arduino.h"` присутствует.

| Библиотека | Версия | Что даёт проекту |
|---|---|---|
| **M5Unified** | **0.3.0** | Инициализация платы: дисплей, тач, батарея (INA226), RTC RX8130, IMU, аудио, IO-экспандеры, питание C6 |
| **M5GFX** | **0.3.0** | Графика: панели ST7121/ST7123/ILI9881C, шрифты, canvas |
| **M5UnitUnified** | **0.6.5** | Фреймворк юнитов, на нём построена клавиатура |
| **M5Utility** | **0.3.1** | Зависимость M5UnitUnified |
| **M5HAL** | **0.1.4** | Зависимость M5UnitUnified |
| **M5Unit-KEYBOARD** | **0.1.0** | Клавиатура A164 (класс `UnitTab5Keyboard`) |

### Что даёт M5Unified бесплатно

| Возможность | API | Ограничение |
|---|---|---|
| Заряд, % | `M5.Power.getBatteryLevel()` | Линейная интерполяция по напряжению, приблизительно |
| Напряжение | `M5.Power.getBatteryVoltage()` | Точно (INA226) |
| Ток | `M5.Power.getBatteryCurrent()` | Положительный = заряд |
| Состояние | `M5.Power.isCharging()`, `getChargeState()` | Только `charging`/`discharging`/`idle`; `full` не выдаётся |
| Управление зарядом | `setBatteryCharge()`, `setChargeCurrent()` | 500/1000 мА |
| Выключение | `M5.Power.powerOff()` | Импульсы через PMS150G |
| Время | `M5.Rtc.getDateTime()/setDateTime()` | Нет периодического timer IRQ |
| Аудио | `M5.Speaker`, `M5.Mic` | В MVP не используется |
| IO-экспандеры | `M5.getIOExpander(0/1)` | Прямой доступ к PI4IOE5V6408 |

Чего **нет** в M5Unified: класса для SD (используем `SD_MMC`), драйвера
клавиатуры A164 (используем M5Unit-KEYBOARD), LVGL-порта.

## 3. Системные библиотеки Arduino

| Библиотека | Источник | Зачем |
|---|---|---|
| `SD_MMC` | Arduino core | SD в 4-bit SDIO, slot 0, IO_MUX — пины из варианта платы |
| `WiFi` | Arduino core | STA-режим через ESP32-C6 (`esp_hosted`) |
| `HTTPClient` | Arduino core | HTTP-клиент для API |
| `NetworkClientSecure` | Arduino core | TLS |
| `Preferences` | Arduino core | NVS для секретов |
| `ESP_HostedOTA` | Arduino core 3.3.5+ | Прошивка сопроцессора C6 (резерв, если Wi-Fi не поднимется) |
| `bblanchon/ArduinoJson` **7.4.3** | PlatformIO (`bblanchon/ArduinoJson@7.4.3`) | Разбор ответа API и строк треда |

ArduinoJson используется **только на разбор**: тело запроса собирается вручную
(`util/api_json`), потому что оно уходит десятками килобайт и лишняя аллокация
на каждое сообщение истории ни к чему. На разборе библиотека оправдана:
недоверенный ввод с экранированием, свой парсер стал бы источником дефектов.

Важная особенность версии 7: **zero-copy не делается даже на изменяемом
буфере**. Строки копируются в пул `JsonDocument`, и указатель на текст живёт
только до выхода из функции разбора. Поэтому `util/chat_line::parse` копирует
текст в буфер вызывающего.

## 6. Как обновлять

1. Проверить, что новая версия платформы содержит board `m5stack-tab5-p4`.
2. Проверить в исходниках `cores/esp32/esp32-hal-hosted.c` наличие `#include "pins_arduino.h"`.
3. Собрать, прошить, проверить на плате: дисплей, клавиатура, Wi-Fi, SD, батарея.
4. Обновить `platformio.ini`, этот файл, `CHANGELOG.md`.
5. Проставить тег, если изменения существенные.

Обновление «на автомате» запрещено: разница в одну минорную версию core уже
ломала SDIO-пины.
