## Р-001. Arduino + PlatformIO (pioarduino), а не ESP-IDF

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Плата ESP32-P4. Официальный `espressif32` в PlatformIO не содержит
ни одного board-файла для P4 — нужна платформа pioarduino. Есть два пути:
Arduino-фреймворк или ESP-IDF с BSP `m5stack_tab5`.

**Решение.** Arduino + pioarduino 55.03.313.

**Обоснование.**

1. **M5Unified даёт почти всё железо бесплатно**: дисплей и тач с автодетектом
   ST7121/ST7123/ILI9881C, батарея через INA226 (`getBatteryLevel`,
   `getBatteryVoltage`, `isCharging`), RTC RX8130 с подстановкой системного
   времени, IO-экспандеры, аудио, пины SD и Wi-Fi. В ESP-IDF то же самое
   пришлось бы дёргать через BSP вручную.
2. **Кириллица в M5GFX — одна строка** (`fonts::lgfxJapanGothic_16`). В LVGL 9.2
   готовых шрифтов с кириллицей нет вообще — ни Montserrat, ни DejaVu, ни SimSun.
   Это проверено разбором cmap, а не по документации.
3. **Клавиатура A164 имеет официальную Arduino-библиотеку** `M5Unit-KEYBOARD`.
4. Задача проекта — ТЗ, а не «красивый UI». LVGL тянет порт драйвера DSI, PPA и
   генерацию шрифтов, то есть самый трудоёмкий кусок, при низкой отдаче.

**Отклонено.**

- ESP-IDF + `m5_tab5_component`: даёт LVGL + PPA + клавиатуру в одном флаконе, но
  батарею/RTC/питание пришлось бы писать самим, а кириллица потребовала бы
  `lv_font_conv`. Больше кода ради косметики.
- Arduino + LVGL поверх M5GFX: двойная буферизация DSI-кадра в PSRAM, лишний трафик
  и всё равно свой шрифт.

**Следствия.** UI пишем на M5GFX сами (список сообщений, формы, статус-бар).
Если позже понадобится «красивый» интерфейс — рендер спрятан за `Screen`, LVGL
можно добавить инкрементально.

## Р-002. Платформа 55.03.313, а не 54.03.21

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** В исследовании платы была зафиксирована `54.03.21` (Arduino core
3.2.1, IDF 5.4.2) — на тот момент это была рекомендованная M5Stack версия.

**Решение.** `pioarduino` 55.03.313 = Arduino core **3.3.13**, IDF **5.5.6**.

**Обоснование.**

1. В `54.03.21` **нет** board-файла `m5stack-tab5-p4` и нет варианта
   `m5stack_tab5` — пришлось бы вручную прописывать SDIO-пины C6.
2. Wi-Fi на P4 требует `esp32-hal-hosted.c`, который появился в 3.3.x. В версиях
   3.3.1–3.3.4 он **не включал** `pins_arduino.h`, из-за чего брались пины
   EV-борды и SDIO не инициализировался (`sdmmc_init_ocr ... 0x107`). Исправление
   вошло только в **3.3.5**. В 3.3.13 `#include "pins_arduino.h"` присутствует —
   проверил в исходниках тега.
3. Board-файл содержит `chip_variant: "esp32p4_es"` — семейство «до 3.0», а наша
   плата именно **rev v1.3** (проверено esptool).

**Следствия.** Первая сборка долгая (качается core + IDF). Обновление платформы —
осознанное действие с проверкой на плате, а не «на автомате».

## Р-003. UI на M5GFX, без LVGL

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Нужны экран чата, список тредов, просмотр документов, редактор,
настройки, статус-бар.

**Решение.** Собственный минимальный набор виджетов поверх M5GFX.

**Обоснование.**

- Готового LVGL-порта для DSI на Arduino нет; `lv_port_esp32`/`lvgl_esp32_drivers`
  ориентированы на SPI/RGB и для P4 непригодны.
- В LVGL 9.2 нет шрифтов с кириллицей — нужен `lv_font_conv` в сборочном процессе.
- Интерфейс по сути текстовый: лента сообщений, поле ввода, формы. Виджеты LVGL
  дают мало, а стоят дорого.

**Следствия.** Своя реализация `MessageList`, `TextInput`, `StatusBar`. Ограничение:
нет анимаций и сложной вёрстки — для этого проекта не нужно.

## Р-004. HTTP-клиент: `HTTPClient` + `NetworkClientSecure`, стриминг SSE

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Ответ модели на 1280×720 нужно показывать по мере генерации. На
плате ~32 КБ internal RAM на TLS-соединение (`MBEDTLS_SSL_MAX_CONTENT_LEN=16384`,
буферы не в PSRAM).

**Решение.** Один `HTTPClient` с `setReuse(false)`, стриминговый парсер SSE,
**одно соединение за раз**.

**Обоснование.**

- Стриминг обязателен: ждать 10–30 с пустого экрана — плохой UX.
- Параллельные запросы не нужны и опасны: 2–3 TLS-соединения уже тесны по internal RAM.
- `LWIP_TCP_SND_BUF_DEFAULT=5760` ограничивает скорость скачивания, но для API это неважно.

**Отклонено.** gzip — требует miniz, экономит трафик, но тратит RAM; трафик здесь не узкое место.

**Следствия.** Агентский цикл последовательный. При ошибке — один ретрай, затем сообщение.

## Р-005. `web_search` — отдельный инструмент, а не плагин в основном запросе

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** У RouterAI веб-поиск — это **плагин запроса** (`plugins:[{id:"web"}]`),
а не отдельный эндпоинт. Отдаёт он не страницу целиком, а ответ модели с
аннотациями `url_citation`. В документации RouterAI есть оговорка, что вместе с
инструментами поиск не выполняется.

**Решение.** `web_search` — отдельный инструмент агента: устройство делает **второй**
запрос к API с плагином и без `tools`, получает источники и выжимки, возвращает их
в цикл агента.

**Обоснование.**

1. Снимает риск конфликта «плагин vs tool calling»: они в разных запросах.
2. Предсказуемость: агент явно решает, когда искать, и видит результат как данные.
3. Прозрачность: вызов виден в чате строкой, источники — в ответе и в файле.

**Отклонено.**

- Плагин в основном запросе (вариант «кнопка Поиск») — оставлен как возможный режим,
  но не как основа: нет контроля, нет явных источников, конфликт с tools.
- Внешний search-API (Tavily/Jina) — отклонён для MVP, чтобы не заводить второй
  биллинг и второй ключ. Абстракция `IWebSearch` оставляет место для реализации позже.

**Следствия.** +1 round-trip и +токены на поиск. Приемлемо.

## Р-006. Секреты в NVS, настройки на SD

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Wi-Fi-пароль и API-ключ надо где-то хранить. SD-карту легко вынуть
и прочитать на компьютере.

**Решение.** Wi-Fi и API-ключ — в NVS. Остальные настройки — в
`/sdcard/config.json`.

**Обоснование.** NVS не читается без дампа флеша и не вынимается вместе с картой.
Несекретные настройки удобно править руками и бэкапить.

**Отклонено.** Шифрование мастер-паролем — избыточно для бытового устройства,
усложняет запуск (ввод пароля при каждой загрузке).

## Р-007. Имена файлов — ASCII-слаги

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Документы по-русски. Кириллица в именах файлов на FAT32 технически
возможна, но на ESP32 это регулярный источник проблем: сравнение имён, VFS,
копирование, сортировка, обмен с компьютером.

**Решение.** Имя файла — латинский слаг (`air-purifier-filter-reset.md`), русский
заголовок — в YAML-фронтматтере (`title:`), показывается в UI.

**Следствия.** Поиск идёт по содержимому, а не по имени. Сортировка списка — по
`updated` из фронтматтера.

## Р-008. Русская раскладка маппится на хосте, режим Normal

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Клавиатура A164 — матрица 5×14 с US ANSI, кириллицы в прошивке нет.
Есть три режима: Normal (`row/col`), HID (modifier+keycode), Character (имя клавиши
строкой). Владелец печатает по памяти, зная расположение русских букв на ANSI.

**Решение.** Режим **Normal** (`0x10 = 0`), собственные таблицы маппинга:
латиница, ЙЦУКЕН, спецклавиши. Переключение — `Ctrl+Space` и тап по индикатору в
статус-баре, состояние в NVS.

**Обоснование.** Character-режим отдаёт готовую латинскую строку, и для кириллицы
её всё равно пришлось бы перемаплять — но уже без `row/col`, то есть с потерей
информации о физической клавише. Normal сохраняет полную свободу.

**Следствия.** Держим в прошивке две таблицы (латиница + ЙЦУКЕН) и обработку
модификаторов. Смена варианта (например, добавить кириллические наклейки) не
требует изменений кода.

## Р-009. Один `default_16MB.csv`, без OTA в MVP

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Заводская прошивка занимает `factory` 10 МБ. Стандартная схема
`default_16MB.csv` даёт два слота по 6.25 МБ.

**Решение.** `default_16MB.csv`, OTA не реализуем в MVP, прошиваем по USB.

**Обоснование.** 6.25 МБ достаточно для LVGL-нет, M5GFX-да + TLS + JSON. Два слота
оставляют место под OTA в 2.0.0 без переразбивки флеша. Включать OTA в MVP — это
ещё один канал доставки кода и ещё один класс отказов.

**Следствия.** Обновление — USB-кабелем. Версия в `include/version.h` и на экране About.

## Р-010. Модель: DeepSeek V4 Flash через RouterAI

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Нужен OpenAI-совместимый API с tool calling, дешёвый на объёмах
бытового ассистента.

**Решение.** `deepseek/deepseek-v4-flash` (алиас `~deepseek/deepseek-v4-flash-latest`)
через `https://routerai.ru/api/v1`.

**Обоснование.** Проверено по `/v1/models`: контекст 1 048 576, поддерживаются
`tools`, `parallel_tool_calls`, `tools_choice`, `reasoning_effort`,
`structured_outputs`. Цена ~4.7 ₽/1M входных и ~11.8 ₽/1M выходных токенов.
Большой контекст снимает необходимость в суммаризации истории.

**Следствия.** Модель задаётся в настройках, а не зашита в код. Поле `model`
свободное — можно переключиться на другую модель RouterAI без перепрошивки.

## Р-011. Цена запроса не показывается

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** В первой редакции интерфейса планировалось показывать стоимость
запроса в рублях.

**Решение.** Показываем только токены (`12.3k → 480 токенов`) и число шагов.

**Обоснование.** Цена зависит от тарифа провайдера и меняется; захардкоженная
ставка станет неверной и будет вводить в заблуждение. Токены — объективный факт.

**Следствия.** В `config.json` остаётся только модель и параметры генерации.
Если понадобится — цену можно добавить как редактируемое поле тарифа.

## Р-012. Текстовый редактор в MVP

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Документы пишет агент, но иногда нужно поправить руками.

**Решение.** Полноэкранный построчный редактор: посимвольный ввод, курсор
(←→↑↓, Home/End), `Backspace`/`Delete`, `Enter`, `Ctrl+S` сохранить, `Esc` выход
с подтверждением, `Ctrl+Z` на 20 последних правок. Без подсветки синтаксиса.

**Обоснование.** ~300–400 строк, закрывает «поправить шаг в инструкции».
Подсветка md — заметная работа при низкой отдаче.

**Следствия.** Редактор — отдельный экран, не связан с агентом.

## Р-013. SD-карта: питание через LDO4 включаем вручную

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** На живой плате `SD_MMC.begin()` падал в
`sdmmc_init_ocr: send_op_cond (1) returned 0x107` (таймаут), при том что карта
исправна и размечена в FAT32.

**Причина.** На ESP32-P4 питание I/O SD-карты идёт от встроенного LDO. Arduino
включает его только если вариант платы задаёт `BOARD_SDMMC_POWER_CHANNEL`, а
вариант `m5stack_tab5` этого не делает. Официальный esp-bsp для Tab5 включает
LDO-канал 4 явно.

**Решение.** Перед монтированием вызываем `SD_MMC.setPowerChannel(4)`. Обёрнуто
в модуль работы с SD, а не размазано по коду.

**Альтернативы.** Свой `sdmmc_host_t` с `pwr_ctrl_handle` — то же самое, но
больше кода; правка варианта платы — правка чужого пакета.

**Следствия.** Без этой строки карта не монтируется вообще, диагностика даёт
ложное «карты нет». Записано в `docs/HARDWARE_VERIFICATION.md`, раздел «Грабли».

## Р-014. Клавиатура A164 — на `Wire` (I2C-порт 0), не на `Wire1`

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** Первая попытка инициализации клавиатуры через `Wire1.begin(0, 1)`
давала `ESP_ERR_INVALID_STATE` и пустую шину, хотя клавиатура подключена.

**Причина.** `Wire1` — это I2C-порт 1. M5Unified при `M5.begin()` уже открывает
его для шины платы (G31/G32), и повторный `begin()` с другими пинами молча
возвращает «уже запущено», оставляя старые пины. Клавиатура при этом висит на
свободном порту 0 (G0/G1).

**Решение.** Клавиатура инициализируется на `Wire` (порт 0) с явными пинами
G0/G1. Официальный пример `KeyMatrixVisualizer` делает так же.

**Следствия.** Внутренняя шина платы (экспандеры, INA226, RTC, IMU) и шина
клавиатуры разведены по разным портам. При добавлении внешних устройств на
ExtPort помнить: порт 0 занят клавиатурой.

## Р-015. Поворот дисплея Tab5 — 3, не 1

**Дата:** 23.11.2026
**Статус:** принято

**Контекст.** При `setRotation(1)` изображение на панели оказалось вверх ногами.

**Причина.** Панель физически 720×1280 (портрет). Ландшафтных поворотов два —
1 и 3, они отличаются на 180°. Какой из них «правильный», зависит от ориентации
шлейфа и монтажа панели в корпусе.

**Решение.** `setRotation(3)` во всех экранах. Значение вынесено в одно место
(инициализация UI), чтобы не расходилось по коду.

**Следствия.** Тач-координаты проверять уже с поворотом 3 — M5GFX пересчитывает
их сам, но фактическое совпадение нажать→нарисовать надо подтвердить.
