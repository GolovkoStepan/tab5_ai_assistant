# План разработки ПО

Документ описывает этапы работы над прошивкой **M5Stack TAB5 AI Assistant**, критерии
готовности каждого этапа и то, что сознательно вынесено за пределы MVP.

Связанные документы:

- [`AGENTS.md`](../AGENTS.md) — сводка по проекту, статус, команды
- [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) — архитектура прошивки
- [`docs/DECISIONS.md`](DECISIONS.md) — журнал принятых решений
- [`docs/DEPENDENCIES.md`](DEPENDENCIES.md) — версии фреймворков и библиотек
- [`docs/BOARD_AI_RESEARCH.md`](BOARD_AI_RESEARCH.md) — исследование платы, распиновка
- [`docs/TAB5_BOARD_FACTORY_MANUAL.md`](TAB5_BOARD_FACTORY_MANUAL.md) — официальная документация M5Stack
- [`docs/HARDWARE_VERIFICATION.md`](HARDWARE_VERIFICATION.md) — что проверено на живой плате

## 1. Цель и границы MVP

**Цель.** Карманный ИИ-помощник для бытовых задач: спрашиваешь — он отвечает, при
необходимости ищет в интернете, а найденное **сохраняет в собственный архив
markdown-документов на SD-карте**, чтобы второй раз не искать.

**Что входит в MVP:**

- диалог с моделью через OpenAI-совместимый API (RouterAI, модель DeepSeek V4 Flash);
- несколько независимых тредов с историей, переживающих перезагрузку;
- инструменты агента: список/чтение/поиск/запись/удаление документов;
- веб-поиск как инструмент агента;
- настройка Wi-Fi и API на самом устройстве;
- ввод с аппаратной клавиатуры A164, включая русскую раскладку;
- индикация заряда и предупреждения о разряде.

**Что не входит в MVP (см. раздел 7):** голос, камера, OTA, рендер markdown,
эмбеддинги, умный дом.

## 2. Технические ограничения, определяющие план

Эти факты установлены по документации, исходникам библиотек и проверкой на живой
плате. Они определяют, что можно сделать дёшево, а что дорого.

| Ограничение | Следствие для плана |
|---|---|
| **P4 не имеет радио.** Wi-Fi — через ESP32-C6 по SDIO (`esp_hosted`) | Нужна pioarduino ≥ 55.03.35; проверять сеть на реальной плате, а не в эмуляции |
| **Наша плата — P4 rev v1.3** (семейство «до 3.0») | Board-файл `m5stack-tab5-p4` с `chip_variant: esp32p4_es` подходит; IDF 5.5.6 работает |
| **TLS ~2×16 КБ на соединение в internal RAM** | Сетевые запросы последовательные, не параллельные; JSON-буферы — в PSRAM |
| **`LWIP_TCP_SND_BUF_DEFAULT=5760`** | Скачивание медленнее, чем позволяет радио; для API-запросов неважно |
| **Кириллица в M5GFX есть из коробки** (`efontJA_16`), **в LVGL 9.2 готовых шрифтов с кириллицей нет** | UI на M5GFX, а не на LVGL — иначе нужен `lv_font_conv` и свой шрифт |
| **Клавиатура A164 отдаёт `row/col`**, кириллицы в прошивке нет | Русская раскладка маппится на хосте (ЙЦУКЕН), переключение `Ctrl+Space` |
| **Дисплей ST7121, 1280×720, нативная ориентация портретная** | Поворот `setRotation(1)`; координаты тача тоже поворачиваются |
| **Батарея: `M5.Power.getBatteryLevel()` линейна по напряжению 2S** | Процент приблизительный; рядом показываем вольты |
| **Нет `getBatteryPresence()`**, `full`/`not_charging` не выдаются | Наличие АКБ — эвристика по напряжению; статус зарядки — по току INA226 |
| **Нет периодического timer IRQ у RX8130** | `timerSleep(seconds)` не работает; нужен абсолютный `timerSleep(rtc_time_t)` |
| **16 МБ flash** (`default_16MB.csv`: 2 слота по 6.25 МБ) | Место под OTA есть, но OTA не в MVP |

## 3. Этапы

Каждый этап заканчивается рабочей прошивкой на устройстве и тегом. Тег ставится
только если все критерии готовности выполнены.

### v0.1.0 — Bring-up

Скелет проекта и проверка железа. Цель — убедиться, что платформа, дисплей,
клавиатура, SD и батарея работают, и зафиксировать это в документации.

**Работы:**

1. `platformio.ini` на pioarduino 55.03.313, board `m5stack-tab5-p4`, зависимости с фиксированными версиями.
2. Дамп заводской прошивки 16 МБ (сделан, см. `docs/HARDWARE_VERIFICATION.md`).
3. Экран приветствия: версия, строка с кириллицей, заряд батареи, PSRAM, flash, частота CPU.
4. Драйвер клавиатуры A164: обёртка над `M5Unit-KEYBOARD` в режиме **Normal** (нужны физические позиции для ЙЦУКЕН) + своя таблица раскладки в `util/keymap.cpp`.
5. Проверка кириллицы на экране (шрифт `efontJA_16` — в `lgfxJapanGothic_16` нет `_`, а `\` нарисован как `¥`, см. Р-017).
6. Монтирование SD (`SD_MMC`, 4-bit, slot 0), вывод объёма и свободного места.
7. Заготовка `SettingsStore` в NVS (Wi-Fi SSID/пароль, API base_url/ключ/модель) + `config.json` на SD для несекретных настроек; файл создаётся при первом запуске.
8. Экран Wi-Fi (`Ctrl+W`): скан сетей, ввод пароля, подключение, индикатор в
   статус-баре; список и проверка пароля — в `util/wifi_list` с тестами на
   хосте, подключение неблокирующее (`hw/wifi`).

**Критерии готовности:**

- [x] Прошивка собирается без предупреждений, `pio run -e tab5` зелёный.
- [x] На экране виден русский текст без «квадратиков», корректные `Ё`, `«»`, `—`.
- [x] Печать с клавиатуры A164 выводит символы; `Backspace`, `Enter`, стрелки работают.
- [x] `Ctrl+Space` переключает РУС/ENG, индикатор в статус-баре меняется.
  *(проверено на плате: в логе `раскладка РУС` / `ENG`, заголовок перерисовывается)*
- [ ] Батарея: процент и вольты совпадают с реальностью (±5 %). *(блокировано
  железом: аппаратного признака наличия АКБ нет, `getBatteryPresence()` —
  `unsupported`, а проценты без тока врут. Проверять при подключённом
  аккумуляторе; см. Р-016)*
- [x] SD смонтирована, показывает объём; после перезагрузки монтируется сама.
- [x] Wi-Fi: скан находит сети, подключение по паролю работает, после перезагрузки поднимается автоматически. *(проверено на плате: скан 16–26 сетей, в списке 12; подключение к «Ufanet-220 2.4G» за 5 с, адрес 192.168.1.77, RSSI −41; после RST — автоподключение за 4.3 с. Пароль сохранён в NVS и в config.json не попадает)*
- [x] `WiFi.setPins()` не требуется — пины подхватываются из board-файла (проверить лог).
- [x] Факты в `docs/HARDWARE_VERIFICATION.md` заполнены (ревизия, MAC, PSRAM, скорость SD).
- [x] `SettingsStore`: секреты в NVS, несекретные настройки в `/sdcard/config.json`;
  файл создаётся при первом запуске и читается после перезагрузки. Запись и
  обратное чтение секретов проверены на живой плате, в `config.json` они не
  попадают.

### v0.2.0 — Чат

Диалог с моделью. Пока без инструментов и без документов — только чтобы разговор
работал надёжно.

**Работы:**

1. `ApiClient`: HTTPS-клиент к OpenAI-совместимому `/chat/completions`, JSON-сборка через ArduinoJson.
2. Стриминг SSE: инкрементальный парсер, отрисовка по мере поступления токенов.
3. `ChatStore`: треды на SD, JSONL на тред, лимит размера, обрезка старых сообщений при отправке.
4. Экран чата: лента сообщений с переносами, поле ввода, индикатор стриминга, отмена по `Esc`.
5. Экран тредов: список, создание, переименование, удаление с подтверждением.
6. Экран настроек API: base_url, ключ, модель, `temperature`, `reasoning_effort`.
7. Счётчик токенов под ответом и за сессию в статус-баре.
8. Обработка ошибок: таймауты, 401, 429 с `Retry-After`, 5xx, обрыв соединения.

**Критерии готовности:**

- [ ] Полноценный диалог: вопрос → стриминговый ответ → продолжение разговора.
- [ ] Перезагрузка не теряет треды и историю.
- [ ] `Esc` прерывает стриминг; частичный ответ сохраняется с пометкой.
- [ ] Ошибки сети показываются понятным текстом, не «зависанием».
- [ ] Токены считаются и отображаются.
- [ ] Юнит-тесты парсера SSE и обрезки истории проходят в `env:native`.

### v0.3.0 — Документы

Превращение чата в агента: модель получает инструменты и ведёт архив.

**Работы:**

1. Реестр инструментов (`ToolRegistry`): JSON-схемы, валидация аргументов, результат/ошибка как текст.
2. Инструменты: `list_docs`, `read_doc`, `search_docs`, `write_doc`, `delete_doc`.
3. `DocStore`: ASCII-слаги, YAML-фронтматтер (`title`, `tags`, `source_url`, `created`, `updated`), автосоздание папок, атомарная запись через временный файл.
4. Валидация путей: запрет `..`, абсолютных путей, выхода за `/sdcard/notes`.
5. Агентский цикл: до 8 шагов, прозрачный лог вызовов в чате, усечение результата до 4 КБ.
6. Экран заметок: список по папкам, поиск, просмотр с прокруткой.
7. Текстовый редактор: посимвольный ввод, навигация, `Ctrl+S`, `Esc` с подтверждением, `Ctrl+Z`.
8. Подтверждение удаления на устройстве.
9. Автогенерируемый `INDEX.md` по содержимому `notes/`.

**Критерии готовности:**

- [ ] Сценарий «найди информацию и сохрани» проходит без ручных действий.
- [ ] Созданный файл открывается на компьютере и читается как обычный markdown.
- [ ] Повторный запрос обновляет существующий документ, а не плодит копии.
- [ ] Агент не может выйти за пределы `/sdcard/notes` — проверено тестом.
- [ ] Удаление требует подтверждения на экране.
- [ ] Юнит-тесты `DocStore` и валидации путей проходят.

### v0.4.0 — Веб-поиск

Агент получает интернет. Ключевой этап для основного сценария использования.

**Работы:**

1. `RouterAiWebSearch`: второй запрос к API с плагином `plugins: [{id:"web"}]` без tools, результат — источники и выжимки.
2. Инструмент `web_search` с `max_results`, подстановка результата в цикл агента.
3. Отображение источников в чате; сохранение `source_url` в фронтматтер документа.
4. Настройка поиска на устройстве: включён/выключен, число результатов, домены.
5. Проверка совместимости плагина с tool calling на практике; при конфликте — раздельные запросы (уже заложено).

**Критерии готовности:**

- [ ] Сценарий «почистил фильтр, забыл как сбросить ошибку» проходит целиком: поиск → ответ → сохранённый документ со ссылкой.
- [ ] Без интернета поиск корректно сообщает об ошибке, агент не зависает.
- [ ] Источники видны в чате и в файле.

## 4. Порядок работ внутри этапа

Чтобы не утонуть, каждый этап идёт одинаково:

1. **Схема** — что за модули, какие интерфейсы, что тестируется. Короткая запись в `docs/ARCHITECTURE.md`.
2. **Логика без железа** — чистые функции и юнит-тесты (`env:native`). Здесь ловится большинство ошибок.
3. **Интеграция** — привязка к M5GFX/сети/SD.
4. **Проверка на плате** — ручной прогон по критериям готовности.
5. **Документация** — `CHANGELOG.md`, `docs/`, сверка с реализацией.
6. **Тег** — только после всего перечисленного.

## 5. Сценарии приёмки

Их прогоняем перед каждым релизом — это проверка, что продукт делает то, ради чего он сделан.

**С1. Бытовой вопрос с сохранением (главный сценарий).**
«Почистил фильтр у очистителя воздуха, как сбросить ошибку?» → агент ищет в
интернете → отвечает по шагам → сохраняет `notes/home/air-purifier-filter-reset.md`
со ссылкой на источник. Через месяц: «как сбросить ошибку очистителя» → агент
находит свой документ и отвечает мгновенно, без интернета.

**С2. Продолжение темы.**
«А что там про замену фильтра?» → агент читает ранее сохранённый документ и
дополняет его.

**С3. Ручная правка.**
Пользователь открывает документ, исправляет шаг, сохраняет. Агент при следующем
запросе видит уже исправленную версию.

**С4. Работа без сети.**
Wi-Fi выключен: документы и история читаются, поиск и чат сообщают об отсутствии
сети, ничего не теряется.

**С5. Разряд.**
Довести батарею до 5 %: появляется предупреждение, всё сохраняется, устройство
выключается.

**С6. Долгая сессия.**
20 сообщений подряд с несколькими вызовами инструментов: нет утечек PSRAM,
интерфейс отзывчив.

## 6. Тестирование и CI

**Юнит-тесты (`env:native`, Unity).** Тестируется всё, что не требует железа:
парсер SSE, сборка JSON-запросов, обрезка истории, YAML-фронтматтер, валидация
путей, поиск по документам, разбор ответов модели с tool calls, маппинг клавиш.

**Что тестами не покрывается** (проверяется руками на плате): дисплей, тач,
клавиатура, Wi-Fi, SD, батарея, реальные сетевые запросы.

**GitHub Actions** (`.github/workflows/ci.yml`):

| Задача | Команда | Когда |
|---|---|---|
| Сборка прошивки | `pio run -e tab5` | каждый push и PR |
| Юнит-тесты | `pio test -e native` | каждый push и PR |
| Форматирование | `clang-format --dry-run --Werror` | каждый push и PR |
| Статический анализ | `cppcheck` | каждый push и PR |
| Проверка документации | наличие `CHANGELOG`-записи под текущую версию | PR в `master` |
| Релиз | сборка `firmware.bin` + артефакт | по тегу `v*` |

Сборка прошивки в CI кешируется по `platformio.ini` — иначе каждый прогон будет
скачивать тулчейн заново.

## 7. После MVP — backlog к 2.0.0

Порядок отражает ожидаемую ценность, а не обязательство.

**2.0.0 — голос и мультимодальность**

- Распознавание речи через облако (аудио с ES7210, AEC уже в железе).
- Синтез речи (ES8388 + динамик).
- Кнопка «говорить» с индикацией записи; ответ вслух по настройке.
- Камера SC2356: сфотографировать шильдик прибора и спросить «что это?».

**2.0.0 — работа с документами**

- Рендер markdown на экране: заголовки, списки, код, цитаты, таблицы как моноширинный текст.
- Векторный поиск по архиву (эмбеддинги через API, хранение в файле на SD).
- Экспорт/импорт архива, синхронизация с компьютером.
- Теги и навигация по ним.

**2.0.0 — эксплуатация**

- OTA-обновление прошивки через Wi-Fi (раздел уже двухслотовый).
- Напоминания: «пора чистить фильтр» через RTC.
- Резервное копирование архива на SD/в облако.

**2.0.0 — периферия платы**

- RS-485: управление внешними устройствами.
- M5-Bus, PORT.A: датчики и модули M5.
- IMU BMI270: жесты, пробуждение поворотом.
- Умный дом: MQTT, Home Assistant.

## 8. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Wi-Fi через C6 нестабилен на нашей ревизии | средняя | Проверяем на v0.1.0; при проблемах — `ESP_HostedOTA` для прошивки C6, настройки `RESET_DELAY_MS` |
| Плагин RouterAI `web` не работает вместе с tool calling | средняя | Уже заложены раздельные запросы; проверяем на v0.4.0 |
| Не хватит internal RAM на TLS + стриминг | средняя | Одно соединение за раз, JSON в PSRAM, `MBEDTLS_SSL_MAX_CONTENT_LEN=16384` |
| Кириллица в каком-то месте отрисуется «квадратиками» | низкая | Проверено на реальном шрифте; тестовая строка на экране bring-up |
| Клавиатура A164 в неожиданном режиме | низкая | Протокол документирован, режим переключается записью в `0x10` |
| Модель плохо вызывает инструменты | средняя | Прозрачный лог шагов; при проблемах — упрощение схем инструментов |
