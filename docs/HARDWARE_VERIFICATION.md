### Грабли, найденные на живой плате

**1. Поворот дисплея.** Панель физически 720×1280 (портрет), поэтому ландшафт —
это поворот 1 **или** 3, отличающиеся на 180°. `setRotation(1)` даёт картинку
вверх ногами; правильный — **`setRotation(3)`**.

**2. SD не монтируется без LDO4.** Вариант платы `m5stack_tab5` в Arduino **не
задаёт** `BOARD_SDMMC_POWER_CHANNEL`, поэтому `SD_MMC.begin()` не включает
питание карты и падает в `sdmmc_init_ocr: send_op_cond (1) returned 0x107`
(таймаут). Официальный esp-bsp делает это явно (`ldo_chan_id = 4`). Обязательный
код перед монтированием:

```cpp
SD_MMC.setPowerChannel(4);
SD_MMC.begin("/sdcard", false);
```

**3. Клавиатура — на `Wire`, а не `Wire1`.** `Wire1` в Arduino — это I2C-порт 1,
на котором M5Unified уже держит шину платы (G31/G32). `Wire1.begin(0, 1, …)`
молча остаётся на старых пинах. Клавиатура живёт на **порту 0** (`Wire`), пины
G0/G1 свободны, конфликта нет.

**4. Разметка флеша задаётся вручную.** PlatformIO не читает `arduino.partitions`
из board-JSON, поэтому `board_build.partitions = default_16MB.csv` прописан в
`platformio.ini` явно. Иначе прошивка не влезает в слот 1.25 МБ.

**5. Полная перерисовка экрана на касание = мерцание.** `fillScreen` + 70
прямоугольников занимают заметное время, и экран успевает мигнуть чёрным.
Для временной графики поверх содержимого (курсор, маркер касания) правильный
путь — `readRect` перед отрисовкой и `pushImage` после:

```cpp
uint16_t backup[45 * 45];
M5.Display.readRect(x - 22, y - 22, 45, 45, backup);   // запомнить
M5.Display.drawCircle(x, y, 14, TFT_YELLOW);           // нарисовать
// ...
M5.Display.pushImage(x - 22, y - 22, 45, 45, backup);  // вернуть как было
```

Сетку из повторяющихся элементов тоже не перерисовывать целиком: сравнивать
состояние с предыдущим и трогать только изменившиеся ячейки.

**6. `lgfxJapanGothic_16` не годится для текста: `\` — это `¥`, `_` не рисуется.**
Шрифт следует JIS X 0201, где байт `0x5C` — знак иены, а не обратный слэш;
а глиф подчёркивания (`U+005F`) в нём **пустой** (`w=0, h=0`). Оба дефекта
не видны на образцах вроде «Съешь ещё этих мягких булок», но ломают редактор:
в коде и путях не отображаются `\` и `_`, а `snake_case`-имена читаются как
`snake case`. Проверять не глазами, а разбором таблицы глифов.

Замена — **`lgfx::fonts::efontJA_16`** (Efont Biwidth, 16 px): покрытие нужного
набора 171 символ из 172 (пустой только пробел, так и должно быть), есть
кириллица, `«»`, `№`, стрелки, `—`, `…`. Цена — +26 КБ флеша.
Разбор делается скриптом `scripts/font_probe.py` — он читает таблицу глифов
и печатает покрытие и форму знаков:

```
$ ./scripts/font_probe.py                      # сравнить все шрифты набора
$ ./scripts/font_probe.py --glyph U+005C       # нарисовать обратный слэш
$ ./scripts/font_probe.py --glyph U+005F       # нарисовать подчёркивание
```

Результат на нашем наборе:

```
lgfxJapanGothic_16   169 из 172   нет: —        пустой: ' ' '_'
efontJA_16           171 из 172                пустой: ' '
efontCN_16           168 из 172   нет: « » —
```

**7. Путь для `SD_MMC.open()` — от точки монтирования, без префикса.**
`SD_MMC.begin("/sdcard")` монтирует файловую систему, поэтому
`SD_MMC.open("/config.json")` открывает `/sdcard/config.json`, а
`SD_MMC.open("/sdcard/config.json")` даёт `/sdcard/sdcard/config.json` и падает
с `ENOENT`. Нашлось на живой плате: конфиг молча не создавался, в логе было
только предупреждение, на экране — ничего подозрительного.

```
[E][vfs_api.cpp:320] VFSFileImpl(): fopen(/sdcard/sdcard/config.json.tmp) failed
```

Пути в `app_config.h` теперь относительные, инвариант закреплён тестом
`test_sd_paths_are_relative_to_mount_point` — он проверяет, что ни один путь
не начинается с `kMountPoint`.

**8. `git ls-files` без `--others` пропускает новые файлы.** `scripts/check.sh`
собирал список для форматтера и cppcheck через `git ls-files`, а он отдаёт
только то, что уже в индексе. Новый исходник до `git add` не проверялся
локально вообще — расхождение всплыло бы только в CI после пуша. Теперь
`git ls-files --cached --others --exclude-standard`.

**9. `strlcpy` есть в macOS и BSD, но нет в glibc.** Тесты с ним проходили
локально и упали бы на линковке в CI (`ubuntu-latest`). В тестах — своя
`copy_str`, в прошивке — тоже, заодно с обрезкой по границе UTF-8.

**10. Действие без события — источник «немых» клавиш.** Три дефекта подряд
оказались одной природы: драйвер делал что-то полезное и возвращал `false`,
то есть клавиша выполняла действие, но из потока событий исчезала.

| Что | Что видел пользователь |
|---|---|
| `Sym`, `Aa`, `Ctrl`, `Alt` обновляли состояние | «Нажал, а счётчик не вырос» — 66 из 70 |
| `Ctrl+Space` переключал раскладку | Буква русская, а метка `[ENG]` — лог и UI врали |
| Счётчик покрытия не менялся при смене раскладки | Заголовок «раскладка ENG» при русской букве |

Правило: **если действие меняет видимое состояние, оно обязано стать
событием.** Потребитель сам решит, печатать ли символ; решать за него —
значит гарантировать расхождение между тем, что на экране, и тем, что в модели.
Символа у модификатора нет — это повод передать `Special`, а не промолчать.

Второй слой той же проблемы: **UI обновляется по изменившемуся состоянию, и
состояний теперь два** — счётчик покрытия и раскладка. Сравнение только по
счётчику оставляло заголовок старым. Любое новое отображаемое значение нужно
добавлять в условие перерисовки, иначе экран и модель расходятся молча.

## 6. Открытые вопросы

1. **`CHG_CURRENT` и `CHG_STAT` на одном бите `E2.P6`** — в шелкографии
   противоречие. В M5Unified заряд управляется через `IOE1.G7` (CHG_EN), статус —
   по току INA226. Проверить при первой возможности.
2. **Card-detect у microSD** — судя по шелкографии, пина нет; определяем по факту
   монтирования.
3. **Режим клавиатуры с завода** — на нашем экземпляре подтверждён **Normal**
   (прошивка v1), `UnitTab5Keyboard` в этом режиме отдаёт позиции матрицы.
4. **Физическая нумерация контактов ExtPort1 и PORT.A** — при пайке переходников
   прозвонить.
5. **Прошивка сопроцессора C6 устарела** — host 2.13.1 против slave 1.4.1.
   Arduino предлагает обновление; на сканирование это не влияет, но перед
   работой с HTTPS стоит обновить.
6. **Процент батареи 91 % при 8.06 В** — выглядит завышенным (у NP-F550
   номинал 7.2 В, полный заряд 8.4 В). Сверить с мультиметром и, если нужно,
   откалибровать кривую в настройках.

### Как определять наличие батареи — эвристика по напряжению НЕ работает

Первая версия кода считала «аккумулятор есть, если INA226 показывает больше
5 В». Это оказалось неверно. Измерения на этой плате **без аккумулятора**:

| Состояние | Напряжение | Ток | Что решила эвристика |
|---|---|---|---|
| Питание USB, сразу после старта | **4.34 В** | 0 мА | «нет» ✅ (случайно) |
| Питание USB, зарядный узел поднялся | **8.37 В** | 0 мА | «есть, 100 %» ❌ |

Причина: без аккумулятора INA226 видит напряжение холостого хода зарядного
узла IP2326, который поднимает USB до ~8.4 В. То есть пустой отсек даёт ровно
то же напряжение, что и заряженный аккумулятор.

**Что есть в M5Unified:**

- `M5.Power.getBatteryPresence()` для Tab5 возвращает `unsupported` — у платы
  нет аппаратного сигнала наличия батареи;
- `M5.Power.getBatteryLevel()` считает проценты **от напряжения** и на пустом
  отсеке честно выдаёт 100 %;
- `M5.Power.getChargeState()` определяет состояние **по току INA226**:
  `> +10 мА` — зарядка, `< -10 мА` — разряд, иначе `idle`.

**Решение.** Наличие батареи достоверно не определяется. Поэтому:
- проценты показываем только когда состояние `charging` или `discharging`
  (то есть ток течёт — значит, аккумулятор реально есть);
- в остальных случаях выводим только напряжение и ток;
- в документации и UI не утверждаем «батареи нет» — это непроверяемо.

Порог `cfg::kBatteryPresentMillivolts` удалён как ошибочный.

## 7. Как повторять проверки

```bash
# Идентификация
~/.platformio/packages/tool-esptool/esptool --chip esp32p4 -p /dev/cu.usbmodem1101 flash-id

# Таблица разделов
~/.platformio/packages/tool-esptool/esptool --chip esp32p4 -p /dev/cu.usbmodem1101 \
    read_flash 0x8000 0x1000 /tmp/parttable.bin
python3 - <<'EOF'
import struct
d = open('/tmp/parttable.bin','rb').read()
for i in range(0, len(d), 32):
    e = d[i:i+32]
    if len(e) < 32: break
    magic, ptype, sub, off, size = struct.unpack('<HBBII', e[:12])
    if magic != 0x50AA: break
    print(e[12:28].split(b'\x00')[0].decode(), hex(off), hex(size))
EOF
```
