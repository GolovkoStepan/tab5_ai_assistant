# AGENTS.md

Краткая сводка по проекту для человека и для ИИ-агентов, которые будут с ним работать.

## Что это

Прошивка для платы **M5Stack TAB5** (ESP32-P4 + ESP32-C6, 5″ 1280×720, аккумулятор
NP-F550, съёмная клавиатура A164). Устройство — карманный ИИ-помощник для бытовых
задач: диалог с облачной моделью, веб-поиск и **собственный архив markdown-документов
на SD-карте**, чтобы однажды найденное решение не искать снова.

Пример использования: очиститель воздуха просит заменить фильтр, хозяин не помнит,
как сбросить ошибку. Ассистент ищет в интернете, отвечает по шагам и сохраняет
`notes/home/air-purifier-filter-reset.md` со ссылкой на источник.

**Живой прогон поиска на плате — 26.11.2026, пройден.** Вопрос про сброс
фильтра Xiaomi: модель сама позвала `web_search` (архив проверила раньше:

1294 байта → ответ по фактам, один блок «Источники:» в конце.
`source_url` заметки из следующего хода — `mi.com/ru/support/article/KA-14885/`,
взятый моделью из истории. «Привет» и «спасибо» — `поиск не было, шагов
агента 0`; «погода в Москве» — второй настоящий поиск, 3 источника;
«HEPA H13 vs H14» — поиска нет, ответ по памяти с оговоркой, что данные не
сверены. Это и есть требуемое поведение: инструмент зовётся по нужде.

Первый заход уронил плату: `Stack protection fault` после прихода источников —
`finish_search()` держал на стеке `web::List` (~6 КБ) и буфер 2 КБ. Исправлено
(буфер из `_tool_out`, `format_result` по указателю), повторный прогон прошёл.
**«Без интернета» закрыто** командой `wifi off` по Serial: ход с `web_search`
оборвался на `connection refused` без оплаты, модели ушёл «поиск не удался
(соединение потеряно)», плата не зависла; `wifi on` вернул сеть.
Подъём радио после `wifi off` занимает **2,3 с**, поэтому `Ctrl+W` сначала
пишет «Включаю радио…», а включает драйвер в следующем кадре; после этого сам
подключается по сохранённой сети. Вернуть сеть можно и без команды.

Прогон идёт командой `ask` по Serial (`util/serial_cmd`,
`scripts/tab5_serial.py`) — без человека у клавиатуры, поэтому повторяем.
`thread` по Serial печатает тред с карты — бесплатная диагностика (ею и найдено
дублирование ссылок), `wifi off` / `wifi on` выключают и включают радио,
`api <адрес>` подменяет адрес API для проверки на своём сервере.
**«Пустая выдача» и отказ поискового сервера закрыты** фальшивым API на
ноутбуке (`scripts/fake_api.py`, Р-042) — эти ветки живым вопросом не
воспроизводятся, а сервер отдаёт их по команде и бесплатно. Им же найдены три
дефекта: повтор после 429/5xx уходил с пустым телом (пользователь видел «сервер
отклонил запрос» вместо повтора), `http://` в адресе API не работал (всегда
создавался TLS-клиент), а после успешного повтора не разобрался бы ответ
(SSE-парсер удалялся и не создавался заново).
Не проверено глазами только переключение полей `Ctrl+A`.
Юнит-тесты (648) и сборка зелёные, `check.sh docker` — зелёный.

Разведка API сделана в два захода: Р-036 (`scripts/web_search_smoke.py`) —
плагин `web` совместим с tool calling, источники приходят в `annotations`, число
результатов — только `max_results`; Р-038 (`scripts/web_search_probe.py`) —
проверил то, чем плагин отличается в нашем режиме (стриминг, второй шаг
агентского цикла, размер события, цена). В прошивке есть `util/web_sources`
(разбор источников, сборка `plugins`), поле `plugins_json` в
`api::RequestOptions`, накопление источников в `hw::ApiClient` и показ их в
ленте чата; `write_doc` подставляет `source_url` из первого найденного
источника, если модель не передала свой. Настройки поиска — в `Ctrl+A`
(«Веб-поиск», «Источников в ответе»), `config.json` остаётся для правки с
компьютера.

Тем же заходом найдено и исправлено три дефекта: событие SSE с источниками
приходит одной строкой до 10 КБ, а буфер строки был 4 КБ — при пяти и более
результатах ссылки терялись молча (теперь предел события 16 КБ, буфера строки
нет); плагин тарифицируется за каждый запрос, и ход агента с ним стоил 6,5 ₽
вместо 2,2 ₽; «Поиск в интернете не дал результатов» не появлялось никогда —
обратный вызов шёл только при непустом списке источников (в Р-040 то же
пришлось починить второй раз: флаг «поиск был» ставился по приходу ссылок).

**Поиск — инструмент `web_search`, а не поле в запросе (Р-040).** Раньше
плагин `web` уходил первым шагом хода, и сервер искал по тексту любой реплики
**всегда** — включая «привет», за ~2,1 ₽. Вывод «API сам решает, искать ли»
был неверным (опровергнут ещё в Р-038 п. 5). Теперь поиск — обычный инструмент
в реестре рядом с архивными: модель зовёт его, когда нужны внешние данные, и
только тогда прошивка делает ОТДЕЛЬНЫЙ запрос с плагином, без `tools` (защита
от рекурсии) и с `reasoning_effort: none`. Пересказ и полные ссылки
возвращаются модели как результат инструмента, цикл агента продолжается;
источники идут в общий список хода, поэтому `source_url` и блок «Источники:»
работают как раньше. В ленте появляется настоящая строка
`инструмент · web_search`, в статусе — «ищу в сети: запрос…».
**«Привет» ≈ 0,02 ₽ вместо 2,17 ₽.** Настройка «Веб-поиск» в `Ctrl+A` убирает
инструмент из списка, не пряча архив. Три вещи, найденные чтением треда
(`thread` по Serial): модель перечисляла ссылки сама markdown-разметкой — в
системный промпт добавлен запрет markdown и дублирования, а на экране разметка
снимается `util/markdown` (`md::plain`: `[mi.com](адрес)` → `mi.com`, чистится
только показ, в треде текст остаётся исходным); печать длинного ответа в
`thread` обрезалась на 1600 байтах, и «источники не дошли» было не отличить от
«не влезли в печать» — теперь печатается хвост и считаются вхождения маркера.

## Основные команды

```bash
# Сборка прошивки
pio run -e tab5

# Прошивка (плата должна быть в режиме download или доступна по USB-JTAG)
pio run -e tab5 -t upload

# Монитор порта
pio device monitor -b 115200

# Юнит-тесты логики на хосте (без железа)
pio test -e native

# ВСЕ проверки CI локально (формат, cppcheck, тесты, сборка)
./scripts/check.sh

# То же в контейнере ubuntu:24.04 — максимально близко к CI
# (включая сборку прошивки на Linux; тулчейн кешируется в docker-томе,
#  повторный прогон ~1.5 мин вместо ~8)
./scripts/check.sh docker

# Только форматирование (нужная версия ставится автоматически)
./scripts/check.sh format

# Дамп заводской прошивки (ДО первой своей прошивки)
~/.platformio/packages/tool-esptool/esptool --chip esp32p4 -p /dev/cu.usbmodem* \
    -b 921600 read_flash 0 0x1000000 backup/tab5-factory-16mb.bin
```

Порт на этой машине: `/dev/cu.usbmodem1101` (может меняться).

> **Про clang-format.** Не вызывай голый `clang-format` из системы: на macOS это
> Apple clang-format 21.0.0, в Ubuntu 24.04 — 18.1.3, и они по-разному
> расставляют отступы у trailing-комментариев. CI падал именно из-за этого.
> `scripts/check.sh` ставит зафиксированную версию (21.1.8) через pip — она
> одинакова на любой ОС.

## Правила работы над проектом

- **Язык.** Код, комментарии, документация, сообщения коммитов — **русский**.
  Идентификаторы в коде — английские (общепринятая практика).
- **Ветка.** Работа идёт в `master`. Коммиты и пуш делает владелец проекта.
- **CHANGELOG.** Ведётся по Keep a Changelog, на русском. Запись добавляется в том
  же коммите, что и изменение.
- **Релизы.** SemVer + аннотированные теги `vX.Y.Z`, этапы описаны в плане
  разработки. Один раз забыли закрыть `[Unreleased]` при выпуске тега — поэтому
  вот порядок, весь в одном заходе:
  1. `CHANGELOG.md`: переименовать `## [Unreleased]` в `## [X.Y.Z] — ГГГГ-ММ-ДД`,
     сверху оставить пустой `## [Unreleased]`, внизу обновить ссылки
     `[Unreleased]` и добавить `[X.Y.Z]` на релиз.
  2. `include/version.h` — `APP_VERSION`, `MAJOR`, `MINOR`, `PATCH`.
  3. Сверить статус в `AGENTS.md`, `README.md`, `docs/DEVELOPMENT_PLAN.md`.
  4. `./scripts/check.sh docker` — зелёный.
  5. Коммит (делает владелец), затем `git tag -a vX.Y.Z -m "..."` и
     `git push origin vX.Y.Z` (обычный `push` теги не отправляет).
  6. Проверить: `git ls-remote --tags origin` — тег должен быть на сервере.
  Тег ставится **на тот коммит, где CHANGELOG уже закрыт**, иначе в истории
  остаётся версия без описания.
- **Перед коммитом:** сверить документацию с реализацией, дополнить при расхождении,
  прогнать `./scripts/check.sh` (это ровно то, что делает CI).
- **Библиотеки.** Максимально используем готовые библиотеки M5Stack; своя
  реализация — только там, где готовой нет (клавиатурный слой, UI, агент).
- **Секреты** (Wi-Fi, API-ключи) — только в NVS на устройстве, никогда в git.

## Структура репозитория

```
.
├── AGENTS.md                  — этот файл
├── CHANGELOG.md               — история изменений
├── README.md                  — обзор для человека
├── platformio.ini             — сборка: env:tab5 (плата), env:native (тесты)
├── include/                   — публичные заголовки
│   ├── app_config.h           — константы и настройки по умолчанию
│   ├── version.h              — версия прошивки
│   ├── util/                  — заголовки чистых модулей
│   ├── hw/                    — заголовки драйверов
│   └── ui/                    — заголовки экранов
├── src/                       — исходники прошивки
│   ├── util/                  — чистые функции (тесты на хосте)
│   ├── hw/                    — драйверы железа
│   └── ui/                    — экраны и отрисовка
├── test/                      — юнит-тесты (Unity, env:native)
├── scripts/                   — локальные проверки (scripts/check.sh)
├── docs/                      — документация
├── .github/workflows/         — CI
└── backup/                    — дампы прошивок (в git не попадает)
```
